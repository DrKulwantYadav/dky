# Reusable camps: admin phase

> Part 3 supersedes the pending-dependency notes below. Camp CSV import is now disabled because it bypassed slots/capacity; public endpoints, notification outbox, and resend are implemented in `202610210002_reusable_camps_backend.sql`. Neither migration has been applied in this task. See `docs/camps-backend.md`.

The existing `/admin/camps` and `/admin/free-camp-registrations` areas now use the shared camp contracts from `lib/camps/contracts.ts`. Admin sessions use `getAdmin`/`requireAdmin`; staff can read, while writes require `admin` or `super_admin` both in the HTTP handlers and database functions.

Apply `supabase/migrations/202610210001_reusable_camps_admin.sql` before testing persistence. This migration has **not** been applied by this task. Until applied, admin reads and saves show an error; they do not claim success. It extends existing camps, sessions and registrations without replacing historical records, creates arrival-window slots and change history, and adds transactional functions for save, duplicate, close, cancellation, check-in, no-show and slot move. A successful save is one database transaction. Repeated saves reuse matching session/slot IDs. Booked windows and schedules cannot be removed or silently changed; capacity cannot fall below active bookings. Cancellation is idempotent and does not renumber tokens. Slot moves reserve the destination before changing the booking, keep the booking reference and record actor, old/new slot and token.

The overview metrics are calculated from all database records by `list_admin_camps`, independent of any visible registration page. Registration filtering, count and pagination use `list_admin_camp_registrations`; private name/mobile/token search is sent in a POST body, not the URL. Filtered CSV export uses the same database filter function and the existing quoted CSV convention. Part 3 disables camp CSV/Excel import because it cannot safely assign a slot or enforce capacity; historical imported rows remain visible.

Part 3 implements the public reads and atomic booking operation in `202610210002_reusable_camps_backend.sql`, using the same slot token sequence as admin moves. It adds a durable notification outbox and abuse-protected resend. The public screens fail closed until the migrations and server configuration are applied; see `docs/camps-backend.md`.

Integration checks after migration and Part 3: create/edit/duplicate/publish/close a camp; verify draft secrecy and publication; repeat a save without duplicate slots; reject edits to booked schedules or capacity below active bookings; verify filtered counts and exports; cancel twice without double release; move to a full slot without changing the original; move to a free slot and inspect token/history; verify staff write denial; complete and retry a public booking with the same submission key.
